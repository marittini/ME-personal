## B. 화면 색 → 앱 전체 테마

- 선택지 4개: **화이트 / 크림 / 먹색 / 블랙**.

| 이름   | 정의                                                                                    |
| ------ | --------------------------------------------------------------------------------------- |
| 화이트 | 크림 테마의 토큰 구성을 따르되 배경·카드를 흰색 계열로 바꾼 새 밝은 테마                |
| 크림   | 지금 밝은 테마 그대로(`reader-theme.css` `[data-theme="light"]`, 배경 `#fbf8f3`)        |
| 먹색   | 지금 어두운 테마 그대로(배경 `#22211f`)                                                 |
| 블랙   | 먹색 테마의 토큰 구성을 따르되 배경·카드를 순수 검정 계열(`#000`)로 바꾼 새 어두운 테마 |

- 고른 색이 `html` 테마 토큰을 바꾼다. 서재·설정·편집창·팝업까지 같은 색. 리더 안에만 덮어쓰던 방식(`data-reader-paper`)은 없앤다.
- "화면 테마(밝게/어둡게)" 칸은 삭제한다.
- 기존 값 이전(처음 불러올 때 한 번): 테마 light→크림, dark→먹색. 리더 화면 색 흰색→화이트, 세피아·노랑·초록→크림, 회색→먹색, 검정→블랙.
- 관련 파일: `styles/reader-theme.css`, `styles/globals.css`(리더 화면 색 규칙 제거), `stores/ui.store.ts`(테마 값·이전), `lib/reader-preferences.ts`, `ReaderWorkspace.tsx`.
- 완료 기준: 4색 각각 서재·리더·설정·편집창 스크린샷(PC·모바일), 기존 저장값 이전 회귀.

## C. 읽기 설정 개편

- **RP와 대화 설정을 따로 저장**: `readerPreferences.roleplay`, `readerPreferences.conversation`. 처음 불러올 때 기존 단일 값을 두 모드에 복사한다. 화면 색·글자 크기 같은 앱 전체 값은 공통.
- 접기/펼치기 그룹:
  1. 화면: 화면 색 4종, 글꼴, 글자 크기 ±1
  2. 문단: 줄 간격, 자간, 문단 간격, 정렬, 폭, 양옆 여백, 들여쓰기(RP만)
  3. 대화(Convo만): 보기 방식, 말풍선 색, 번역문 크기
  4. 음성(기본 접힘): 음성 읽기, 감정 지시, 대사 음성 버튼, 대사 화자 방식, 대사 음량, 페르소나 보이스
- 떠 있던 **"방별 음성 설정" 창(`TTSRoomMenu`)과 아이콘을 없애고** 항목을 4번 그룹으로 옮긴다. 저장 위치는 그대로라 기존 값 유지.
- 관련 파일: `ReaderWorkspace.tsx`(설정 창을 별도 컴포넌트로 분리), `TTSRoomMenu.tsx`, `lib/reader-preferences.ts`, `stores/ui.store.ts`.
- 완료 기준: RP에서 바꾼 값이 Convo에 영향 없음, 기존 값 보존 회귀, 음성 항목이 설정 창에서 저장·적용, 떠 있는 음성 아이콘 없음.

## D. 몰입 모드

- 켜면 상단바, 입력창, 리더 위에 떠 있는 아이콘(채팅 설정 버튼, 패키지 창 버튼, 트래커 등) 전부 숨김. 글만 남는다.
- 상단바 다시 부르기:
  - PC: 화면 위쪽 가장자리(약 48px)에 마우스를 올리면 상단바가 내려온다.
  - 모바일: 화면 위쪽 가장자리를 누르면 상단바가 나타난다(가운데 누르기는 글 선택·형광펜과 겹쳐 쓰지 않음).
  - 나타난 상단바에서 몰입 모드를 끈다. 잠시 뒤 다시 숨는다.
- 생성 중에도 숨김 유지, 생성은 그대로 진행.
- RP에서만 제공(Convo는 쓰지 않음).
- 관련 파일: `ReaderWorkspace.tsx`, `globals.css`(`data-reader-focus` 규칙 확장), 채팅 설정 버튼·창 버튼 컴포넌트.
- 완료 기준: 몰입 중 화면에 보이는 조작 요소 0개(E2E로 보이는 버튼 수 확인), PC 호버·모바일 가장자리 탭으로 상단바 표시와 종료.

## E. 캐릭터·페르소나 편집창 인포시트

참고: 손으로 쓴 캐릭터 프로필 시트(흰 종이, 가는 표 선, 왼쪽 위 큰 사진 칸, 칸마다 작은 굵은 라벨 + 값). 깔끔함이 우선.

- **입력칸 자체가 시트의 칸**이다. 입력 테두리·배경을 없애고 표 선이 칸 경계가 된다. 칸을 누르면 그 자리에서 입력. 별도 읽기용 카드는 두지 않는다.
- 라벨: 작고 굵은 글씨(현재 글꼴), 값: 본문 크기. 색은 B의 테마 토큰.
- **사진 칸**: 왼쪽 위 약 1/3 폭, 3:4 고정. 잘린 결과만 표시. "아바타 자르기"를 누르면 자르기 화면을 별도 창으로 연다 → 정사각형·가로형 원본도 칸을 넘지 않음(실기기 캡처의 침범 문제 해결).
- **탭 단위 전환**: 탭을 누르면 그 섹션만 보인다(지금의 긴 스크롤 대신). 탭을 바꿔도 편집 중 값과 저장 흐름 유지.
- **모든 탭**에 같은 스타일 응용(기능·저장 흐름은 그대로, 배치와 표시만):

| 탭                       | 시트 배치                                                                                                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 메타데이터               | 사진 칸 / `이름·버전`, `부제`, `제작자`, (페르소나) `발음 표기 이름` / `태그` 한 줄 / `수다스러움·자동 버전` / `제작자 노트` 긴 칸. 버전 기록·ID 복사는 시트 아래 "관리" 줄 |
| 카드                     | 요약·설명·성격·배경·외모·시나리오·대사: 왼쪽 라벨 칸 + 오른쪽 긴 값 칸                                                                                                      |
| 온보딩·대화(콘보 프로필) | 질문/항목마다 라벨 칸 + 값 칸                                                                                                                                               |
| 로어북                   | 연결된 로어북 목록을 표로                                                                                                                                                   |
| 스프라이트·갤러리        | 이미지 칸 격자                                                                                                                                                              |
| 색상·음성·통계·고급      | 설정 항목마다 라벨 칸 + 조작 칸                                                                                                                                             |

- 모바일: 사진 칸이 위에 전체 폭, 칸은 한 줄에 하나(두 칸 행은 폭이 되면 유지).
- 관련 파일: `characters/CharacterEditor.tsx`, `personas/PersonaEditor.tsx`, 공통 시트 칸 컴포넌트(신규, 두 편집창이 함께 씀), `globals.css`의 `.mari-profile-sheet` 규칙 대체.
- 완료 기준: 탭마다 PC·모바일 스크린샷, 가로형 원본 이미지로 침범 없음, 기존 편집·저장 E2E 통과.

## F. 통합 기억 개편 (2차)

사용자 결정: 통합 기억만 쓴다(고급 메모리·Long-Term Memory·Memory Nag·기억 회상 사용 안 함). 정리는 사용자가 요청할 때만, 이후는 완전 자동.

### F-1. 실행

- **정리 시작은 사용자 버튼으로만.** 답장 생성 뒤 자동 실행 금지(스와이프·재생성으로 답장이 바뀌기 때문).
- 버튼 뒤 과정은 전부 자동: 묶음 나누기 → 추출 → 바로 확정(검토 대기 없음) → 대상별 갱신·이력 이동 → 예산 관리.
- 확정 기록을 남기고 묶음 단위로 되돌리기.
- 통합 기억이 켜진 RP에서는 고급 메모리·기억 회상이 프롬프트에 들어가지 않게 고정하고, 설정 화면에 표시.

### F-2. 기억 계층과 예산

| 계층   | 내용                               | 넣는 조건                                                     | 기본 예산                                  |
| ------ | ---------------------------------- | ------------------------------------------------------------- | ------------------------------------------ |
| 항상   | 진행 중 약속, 사용자가 고정한 사실 | 매 턴                                                         | 600토큰, 넘치면 대기(삭제 없음, 화면 표시) |
| 떠오름 | 그 밖의 현재 사실                  | 최근 대화가 키워드·조합 조건에 맞거나 임베딩 유사도 기준 이상 | 12개 + 토큰 상한                           |
| 흐름   | 묶음 요약(최근)·core·gist          | 최근 N묶음 항상, 이전은 관련 있을 때                          | 남은 예산                                  |

- 사실마다 `activation: always | recall`(기본: 약속 always, 나머지 recall).
- 예산 단위는 토큰 하나. 화면에 "이번 턴 약 N토큰: 항상/떠오름/흐름" 표시.
- 떠오름 판정: 식별용 별칭과 호출 키워드 분리, 조합 조건(한 줄 단어가 모두 나와야), 원문 언어 + 한국어 키워드.

### F-3. 정보 격리 (AI가 소설 전체를 씀)

- 기록: 사실마다 `knownBy`(아는 인물·페르소나), `unknownTo`(명시적으로 모름). 앎이 바뀌는 사건 "B가 X를 알게 됨(메시지 N)"을 기록하고, 비밀 공개는 기존 사실의 `knownBy` 확장으로 처리(새 사실 금지). 전언은 출처 붙은 `belief`.
- 추출 지시: 장면에 없던·엿듣지 않은 인물, 혼잣말·속마음은 모름. 특정 인물에게 숨긴 메시지는 그 인물의 근거로 쓰지 않음.
- 주입:
  - 한 인물만 쓸 때: 그 인물이 아는 것만.
  - 여러 인물을 한 번에 쓸 때: 비밀도 넣되 `<knowledge_boundaries>` 묶음으로 "A만 앎(B·C 모름)"을 표시하고, "각 인물은 자기가 아는 것만 말하고 행동하며, 모르는 인물은 추측·우연으로도 알아차리지 않는다. 비밀은 이야기 안에서 드러나는 장면이 나올 때만 공개된다"는 고정 지시를 함께 넣는다.
  - 공개 요약(흐름)에는 비밀을 쓰지 않는다.

### F-4. 요소 기억 증식 관리

- 원인: 추출 때 기존 사실을 최근 40개만 보여 줌, 같은 항목 판정이 키 완전 일치뿐.
- **대상(entity) 목록**: 이름, 한·영 별칭, 종류. 사실은 "대상 + 속성(소유자·위치·상태·관계·취향 등)" 칸에 붙는다.
- 같은 칸에 새 값 → **현재 값 교체 + 이전 값 이력**(보관함 갱신 방식). 복사 생성 금지.
- 대상당 현재 사실 최대 8개, 넘치면 이력으로(삭제 없음).
- 추출 요청에 이번 묶음에 이름·별칭이 나온 대상 전체 + 진행 중 약속을 넣는다(40개 제한 폐지). 출력은 "대상 ID + 속성 + 새 값".
- 서버 검증: 새 대상의 이름·별칭이 기존 대상과 겹치면(대소문자·공백·한영 별칭 무시) 기존 대상으로 합친다.
- 이미 쌓인 기억: 기억 창의 "기억 정리(합치기)" 버튼(요청 시에만)으로 같은 대상끼리 자동 합치기, 되돌리기 가능.

### F-5. 데이터 안전·성능

- 형식이 어긋난 묶음은 건너뛰고 나머지를 살린다. 원본을 읽지 못하면 쓰지 않는다(현재 코드는 묶음 하나만 어긋나도 전체를 빈 기억으로 읽고, 켜기·끄기 저장 때 덮어쓸 수 있음).
- 저장 형식 v2: v1은 읽을 때 해석, 처음 v2로 쓸 때 v1 원본을 백업 필드에 한 번 보존.
- 생성 한 번에 기억·메시지 목록을 한 번만 읽는다.

### F-6. 화면

- 개요: 이번 턴에 들어간 기억(기존 `committedMemoryReceipt`)과 토큰 막대, 예산 대기 항목, 대상·사실·이력 개수, 중복 의심 개수, 최근 확정 기록과 되돌리기.
- 탭: 약속 / 대상(요소) / 흐름. 항목마다 항상·떠오름 전환, 키워드·조합 조건 편집, 근거 메시지로 이동, 누가 아는지 표시.

### F-7. 완료 기준

- 회귀: v1 읽기·어긋난 묶음 건너뛰기·쓰기 거부 / 계층별 예산 / 키워드·조합 판정 / 같은 대상·속성 갱신 시 개수 불변·이력 증가 / 별칭 합치기 / 대상당 8개 상한 / 한 인물 생성에 남의 비밀 없음 / 병합 생성에 "모름" 표시와 함께 있음 / 비밀 공개 후 반영 / 숨긴 메시지 근거 제외 / 정리는 요청 없이는 실행되지 않음.
- 측정: 긴 RP 하나로 수정 전후 프롬프트 토큰과 사실 개수 비교, 노트에 기록.
- 실기기: 비밀을 하나 심고 몇 턴 진행해 모르는 인물이 아는 척하지 않는지(사용자 확인).

## 2. 진행 순서

1. A — Convo 정리(실사용 오류)
2. B + C — 화면 색과 읽기 설정(설정 창을 한 번에 재구성)
3. D — 몰입 모드
4. E — 편집창 인포시트(메타데이터 → 나머지 탭)
