## 2. 번역 프리셋·단어장 (캡처 2, 3)

### 관찰

- 현재 UI(`NativeIntegrationSettings`, `TranslationIntegratedTools`)는 순정 번역 설정과 **분리된 별도 폼**이다.
  원본 확장(v1.6.4)을 적용한 순정 엔진의 UI와 배치·흐름이 많이 다르다.
- 프리셋을 골라도 순정 "수신 응답 프롬프트 / 발신 메시지 프롬프트" 칸은 바뀌지 않는다.
  현재 구현은 번역 요청 시 서버(`integratedTranslationInput`)가 프롬프트를 몰래 바꿔 끼운다.
  - 결과 1: 화면에 보이는 프롬프트와 실제 프롬프트가 달라 "적용이 안 되는 것"처럼 보인다.
  - 결과 2: 진실의 원천이 두 개(순정 프롬프트, 통합 설정)다.
- `fix/reader-errors`의 가짜 AI 서버 회귀(`translation-presets-live`)에서 서버 경로는 프리셋·단어장·말투를 요청에 넣는 것을 확인했다.
  그러나 사용자가 보는 순정 칸과 불일치하므로 설계를 원본 방식으로 되돌린다.

### 원본 확장의 동작 (근거: 확장 `extension.js` `applyPresetToNative`, `injectPanels`)

- 순정 채팅 설정의 번역 섹션(`[data-chat-settings-section="translation"]`) **안에** 패널을 붙인다.
- 프리셋을 고르면 그 프롬프트를 순정 "캐릭터 응답 번역 프롬프트"(수신) / "유저 입력 번역 프롬프트"(발신) 칸에 **직접 써 넣는다**.
  - "표시했습니다. 저장하면 적용됩니다."라고 안내하고, 사용자가 저장하면 순정 저장 경로로 반영된다.
  - `replace: false`("채팅 설정 유지")는 처음 칸에 있던 원래 프롬프트로 되돌린다.
- 단어장·말투(인풋 보이스)·기타 지침·이전 대화 Context·로어북 참조는 같은 패널 안에서 방별로 설정하고, 번역 요청 시 덧붙인다.

### 설계 (다음 업데이트)

1. 순정 번역 섹션에 통합한다(별도 폼 제거). 프리셋 선택 → 순정 프롬프트 칸에 써 넣기 → 순정 저장. 프롬프트의 진실의 원천은 순정 칸 하나.
2. 서버는 프리셋 프롬프트로 바꿔 끼우지 않는다. 단어장·말투·Context·로어북 덧붙임과 `{{voice}}`/`{{vocab}}` 채움만 유지한다.
3. 내장 프리셋 16개는 공유 상수(`translation-presets.ts`, 원본과 동일)를 그대로 쓴다. 사용자 프리셋 생성·수정·삭제는 같은 패널에서 한다.
4. 기존 데이터 이전: 방에 `presetId`가 저장돼 있고 순정 칸이 비어 있거나 기본값이면, 처음 열 때 그 프리셋을 칸에 표시하고 저장을 안내한다. 사용자가 직접 쓴 순정 프롬프트는 덮어쓰지 않는다.
5. 단어장 입력은 원본처럼 `원어=번역어` 줄 단위 일괄 입력도 지원한다(현재는 행 단위만).

결정 필요(사용자): 패널 배치를 원본 확장 화면과 똑같이 맞출지, 순정 디자인 토큰에 맞춘 같은 흐름이면 될지.

## 3. TTS 버튼 하단 몰림 (캡처 4, 5)

### 관찰

- 엔진 패치 **이후** 받은 답장: 버튼이 대사 옆에 정상 표시.
- 패치 **이전** 받은 답장: 버튼(＋/⋮ 10개)이 메시지 아래에 몰림. 화면에 태그 문자열은 보이지 않음.

### 원인 후보

- (a) 예전 번역문에 오디오 태그가 남아 있어 `id="…"`가 대사로 세어짐 → `fix/reader-errors`에서 수정(번역문 표시 시 숨김).
  다만 캡처 4에 태그가 보이지 않으므로 이 경우만으로는 설명되지 않는다.
- (b) 예전 번역문의 따옴표 수가 원문 대사 수와 다름. 번역 모델이 따옴표를 합치거나 나누거나 「」로 바꾸거나 태그를 버린 경우다.
  현재 규칙은 "개수가 다르면 추측하지 않고 하단 행으로 표시"이므로, 설계상 하단으로 간다. **가장 유력.**
- (c) DOM 갱신 타이밍: 컨트롤 자리(span)를 React가 관리하는 노드에 직접 덧붙이는 방식이다(`DialogueSpeechControls` `useLayoutEffect`).
  재렌더나 번역 전환 때 자리가 사라지면 하단으로 떨어질 수 있다. 사용자 지적 2번(정규식·DOM 갱신)과 연결된다.

### 재현 자료 요청

예전 답장 1개의 원문 `content`와 `extra.translation`이 필요하다. 채팅 내보내기 JSON이나 해당 메시지 복사본이면 된다.
(b)인지 확정하고, 그대로 E2E 고정 자료로 쓴다.

### 설계 (다음 업데이트)

1. 문단 단위 대응 폴백: 따옴표 수가 다르더라도 원문·번역 문단 수가 같으면(`splitMessageParagraphs` 기준), 각 대사가 속한 원문 문단을 찾는다. 그리고 번역문의 같은 번호 문단 끝에 컨트롤을 붙인다. 문단 수도 다르면 지금처럼 하단에 둔다(추측 금지 유지).
2. 컨트롤 자리를 React 렌더링 단계에서 만든다. 대사 표시(`data-tts-dialogue`)에 그룹 번호를 함께 렌더링하고, 컨트롤은 포털 대상으로 React가 소유한 노드를 쓴다. DOM 직접 수정(append)을 없애 재렌더·번역 전환·스트리밍 중에도 위치를 유지한다.
3. 대사 탐지 정규식은 태그 숨김 뒤의 표시 텍스트에서만 돌린다(속성값 따옴표 오인 방지, `fix/reader-errors`에서 일부 적용).

## 4-1. 추가 요청 (2026-10-23 15:28, 캡처 2장)

  - 예: `머스캣맛 파우치` 아래 `- 브랜치 1`, `- 브랜치 2`
  - 근거 데이터: 채팅 메타데이터 `branchParentChatId`(바로 위 원본 채팅), `branchName`(표시 이름). 브랜치의 브랜치는 한 단계 더 들여 쓴다.
  - 기존 이동·이름 변경·삭제는 유지한다. 인계서 P2 "읽기 기록 목차형 디자인"과 같은 작업이며, 실패 중인 "reading index" E2E도 함께 정리한다.

### 캐릭터/페르소나 편집창 (참고: 캐릭터 프로필 시트 인포그래픽)

- 단순하고 최소한의 **캐릭터 프로필 시트** 느낌으로 바꾼다. 사진 + 이름·소속 같은 핵심 칸이 표처럼 정리되고, 아래로 항목별 칸이 이어지는 구성이다.
- PC·모바일 각각 조작하기 좋은 반응형으로 만든다(모바일: 한 줄 쌓기, PC: 사진·기본 정보 2단).
- 주의: 편집 기능·탭·저장 흐름은 그대로 두고 **배치와 표시 방식만** 바꾼다. 서재 꾸미기(표지·표시 정보) 위치는 기존 결정대로 편집창 안에 둔다.
- 결정 필요: 어떤 항목을 시트의 위 칸(요약)에 둘지(예: 이름, 제목/부제, 태그, 제작자·버전).

### CONVO 모드

1. **상단바를 아이메시지 스타일로**: 가운데 프로필 사진과 이름, 좌측 뒤로 가기 형태. 리더 공통 상단바 정리(1번 항목)와 충돌하지 않도록 CONVO 전용 배치로 만든다.
2. **버블 색 커스텀**: 캐릭터·페르소나별 버블 배경색과 글자색을 쉽게 바꾸는 설정. 저장 위치(카드별/방별)는 결정 필요. 기존 테마 색은 기본값으로 쓴다.
3. **TTS 버튼 방식 변경**: 원본 확장(v4.3.2 `unified-tts.js`)의 CONVO 방식을 따른다.
   - 메시지 단위 버튼 하나("음성 생성"): 메시지 액션 줄에 두고, 메시지 원문 전체를 읽는다.
   - 저장된 음성이 있으면 첫 말풍선 머리에 "다시 듣기" 버튼을 둔다. 재생성 전에는 확인을 받는다.
   - 대사별 버튼(RP 방식)은 CONVO에서 쓰지 않는다. 3번 항목의 대사별 배치 수정은 RP 전용이 된다.
4. **프로필 사진 위치**: 버블 모드에서 캐릭터 프로필 사진을 말풍선 묶음의 아래에서 **위**로 옮긴다.

1. 번역문에도 마크다운을 적용한다. 현재 CONVO의 번역문은 일반 텍스트(`ConversationMessageTranslation`)라 `*기울임*`, `**굵게**`가 그대로 보인다. RP는 이미 렌더링하므로 같은 렌더러를 쓴다.

- 번역: 가짜 AI 서버 회귀로 실제 요청 프롬프트 확인 + 순정 칸 표시 E2E.
- 기존 실패 목록(`CLAUDE.md`)은 수정 전 `main`과 비교해 회귀 여부 판단.
- 실기기(Termux/Android) 확인은 사용자에게 요청하고, 확인 전에는 "미검증"으로 표기.
