# Marinara 서재 셸 제품·엔지니어링 설계

상태: 구현 준비 설계안  
범위: Marinara Engine 코어 UI·서버, 모바일 우선

## 1. 제품 원칙

Marinara의 바깥 화면은 공공장소에서도 자연스러운 개인 전자책 서재처럼 보여야 한다. AI 관련 조작은 작품을 연 뒤 필요한 순간에만 드러낸다. 생성, 편집, 스와이프, 번역, TTS, 통화, 에이전트, 기억, 분기, Conversation·Roleplay 연결 등 기존 채팅 기능은 모두 보존한다.

시각 언어는 충분한 여백, 편집물에 가까운 타이포그래피, 얇은 구분선, 사용자가 정한 단일 지향색으로 제한한다. 대시보드식 카드 격자, 장식용 그라데이션, 네온, 글래스 블러, 상시 도구막대, 중복 메타데이터는 사용하지 않는다.

## 2. 용어와 엔진 개념의 대응

| 사용자에게 보이는 용어 | 엔진 개념 | 구현 규칙 |
| --- | --- | --- |
| 작품·도서 | `library_works` 행 | 표시와 그룹화만 담당하며 메시지를 소유하지 않는다. |
| 작가 | 주 캐릭터 이름 또는 사용자 지정값 | 그룹 채팅은 별도 작가명을 쓸 수 있다. |
| 독서 기록 | 기존 `chat` | 한 작품에 여러 기록과 분기를 담을 수 있다. |
| 본문 | `roleplay` 채팅 | 기존 Roleplay 생성·메시지 경로를 사용한다. |
| 서신 | `conversation` 채팅 | 기존 Conversation·통화 경로를 사용한다. |
| 모험 | `game` 채팅 | 기본 화면에서는 숨기고 작품 더보기에서 제공한다. |
| 새 문장 | 기존 영속 unread 값 | 시간값으로 추정하지 않는다. |
| 최근 위치 | 신규 읽기 위치 | 메시지 ID, 스와이프 번호, 문장 내부 위치를 저장한다. |
| 목차 | 사용자 책갈피 지점과 기존 분기 | 임의의 장을 만들지 않는다. |
| 메모·하이라이트 | 신규 개인 주석 | 명시적 선택 없이는 프롬프트로 보내지 않는다. |

화면 문구는 현지화할 수 있지만 API와 타입 이름은 기술적으로 명확한 이름을 유지한다.

## 3. 정보 구조와 화면 이동

```text
홈
 ├─ 이어 읽기 → 작품 정보 → 본문·서신·모험 → 기존 채팅 화면
 ├─ 최근 작품 → 작품 정보
 └─ 서가 → 작품 목록 → 작품 정보

독서 기록
 ├─ 최근 읽은 위치
 ├─ 하이라이트
 ├─ 메모
 └─ 책갈피

설정
 ├─ 서재 표시
 ├─ 읽기 설정
 └─ 고급 생성 설정 → 기존 채팅 설정
```

작품 모드는 전역 전환 탭으로 노출하지 않는다. 사용자는 먼저 작품을 고르고, 작품 안에서 본문·서신·모험 가운데 실제로 존재하는 기록을 연다.

## 4. 데이터 모델

### 4.1 작품

작품은 기존 채팅을 묶는 얇은 표시 계층이다.

```ts
interface LibraryWork {
  id: string;
  title: string;
  authorLabel: string | null;
  primaryCharacterId: string | null;
  coverAssetId: string | null;
  coverCrop: AvatarCrop | null;
  description: string | null;
  shelfId: string | null;
  sortOrder: number;
  hidden: boolean;
  createdAt: string;
  updatedAt: string;
}
```

`chats`에 nullable `libraryWorkId`를 추가한다. 한 작품은 여러 채팅을 포함할 수 있고 한 채팅은 최대 한 작품에만 속한다. 메시지는 기존 테이블에 그대로 남는다.

### 4.2 서가

기존 `libraryFolderScopeSchema`에 `works`를 추가하고 기존 `library_folders` API를 재사용한다. 작품은 최대 한 서가에 속하며 이동 작업의 기준도 기존 폴더 API로 통일한다.

### 4.3 읽기 위치

```ts
interface LibraryReadingState {
  chatId: string;
  messageId: string | null;
  swipeIndex: number | null;
  intraMessageOffset: number | null;
  updatedAt: string;
}
```

스크롤 저장 때문에 채팅 정렬이나 큰 metadata 값이 계속 갱신되지 않도록 별도 테이블에 둔다. 스크롤 정지 후 지연 저장하고 화면을 떠날 때 한 번 더 저장한다. 복원은 메시지 ID를 먼저 찾고 해당 메시지가 렌더링된 다음 내부 위치를 적용한다.

### 4.4 주석

```ts
interface ReaderAnnotation {
  id: string;
  workId: string;
  chatId: string;
  messageId: string;
  swipeIndex: number;
  kind: "bookmark" | "highlight" | "note" | "checkpoint";
  startOffset: number | null;
  endOffset: number | null;
  selectedText: string | null;
  note: string | null;
  title: string | null;
  createdAt: string;
  updatedAt: string;
}
```

범위는 활성 스와이프 본문을 기준으로 한다. 해당 스와이프가 편집되면 주석을 삭제하지 않고 범위만 재연결 필요 상태로 바꾼다. 메시지 ID가 남아 있으므로 책갈피와 사용자 목차 지점은 계속 유효하다.

## 5. 기존 데이터 처리

시작할 때 기존 채팅 전체를 일괄 변경하지 않는다.

1. 서재 API는 명시적으로 만든 작품과 가상 작품을 함께 반환한다.
2. 가상 작품은 `connectedChatId`로 연결된 Conversation·Roleplay를 묶고, 연결이 없으면 채팅 하나를 작품 하나로 본다.
3. 제목은 채팅명, 작가는 주 캐릭터, 표지는 채팅 배경 또는 캐릭터 이미지를 사용한다.
4. 사용자가 제목·표지·서가·숨김을 수정하거나 다른 채팅을 추가할 때만 실제 작품 행을 만든다.
5. 작품에서 새 기록을 만들면 `libraryWorkId`를 즉시 기록한다.
6. 작품 삭제의 기본 동작은 묶음 정보만 삭제하고 채팅은 보존한다. 작품과 채팅을 함께 지우는 별도 파괴적 동작에는 삭제 대상을 명시한다.

이 방식은 큰 설치 환경에서도 초기 마이그레이션으로 화면이 막히지 않으며 기존 가져오기와 백업 형식을 유지한다.

## 6. 화면 설계

### 6.1 홈

홈에는 이어 읽기 한 건, 최근 작품 최대 세 건, 서가 진입, 눈에 띄지 않는 새 작품 버튼, 하단 내비게이션만 둔다. 하단 항목은 홈·서재·기록·설정이다. 캐릭터 태그, AI 상태, 모델명, 모드 배지, 전역 모드 전환은 표시하지 않는다.

이어 읽기는 가장 최근 `reading_state`의 작품을 쓴다. 읽기 위치가 없으면 최근에 연 작품을 사용하고, 둘 다 없으면 최근 작품만 보여준다.

### 6.2 서재

표지를 기본 탐색 단위로 삼는다. 검색 대상은 작품 제목, 작가명, 채팅명, 캐릭터명, 기존 태그다. 필터는 전체·최근·새 문장·즐겨찾기·숨김으로 제한한다. 길게 누르면 서가 이동·작품 정보·숨기기·삭제가 열린다.

화면에 보이는 표지만 썸네일 크기로 불러오고 화면 밖 이미지는 지연 디코딩한다. 목록은 작품 수가 많을 때 가상화한다.

### 6.3 작품 정보

제목, 작가, 표지, 설명, 포함된 독서 기록, 등장인물, 주석, 작품 설정을 보여준다. 주 동작은 한 개만 둔다.

- 마지막으로 연 기록이 있으면 `이어 읽기`
- 기록이 없으면 `읽기 시작` 후 본문·서신 선택 시트
- 둘 이상의 모드가 있으면 주 버튼 아래에 작은 본문·서신 선택
- 모험은 마지막으로 연 모드가 아닌 한 더보기 안에 배치

`새 독서 기록`은 같은 작품 아래 새 채팅을 만들며 기존 기록을 초기화하거나 덮어쓰지 않는다.

### 6.4 본문 뷰어

기존 Roleplay 채팅과 메시지 ID를 그대로 사용한다. 기본 상태는 본문, 인라인 미디어, 입력창만 보인다. 최신 답변을 누르면 듣기·번역·편집·스와이프 위치·재생성·더보기가 나타나며, 과거 메시지는 탭 또는 길게 누르기로 같은 기능에 접근한다.

입력창은 모바일 키보드와 겹치지 않도록 고정한다. 장면 지시와 OOC는 추가 메뉴 안에 둔다. 생성 중에는 짧은 상태 문구와 중단 버튼 하나만 표시한다.

### 6.5 서신 뷰어

기존 Conversation 채팅, 상태, 선톡, 통화, 메시지 동작을 사용한다. 전화 버튼은 장식이 아니라 기존 통화 시작 동작에 직접 연결한다. 통화 중에는 헤더 아래 한 줄짜리 통화 바만 추가하고 대화 내용과 입력창은 계속 사용할 수 있어야 한다. 마이크 버튼은 만들지 않는다.

### 6.6 읽기 설정

한 화면에 모든 설정을 늘어놓지 않고 단계적으로 연다.

1. 표시: 테마, 글꼴, 크기, 줄 간격, 문단 간격, 좌우 여백, 정렬, 미디어 너비
2. 동작: 입력창 고정, 키보드 위 최신 답변 유지, 상황별 도구 표시
3. 언어·음성: 번역 표시 방식과 TTS
4. 고급: 기존 채팅의 모델·프롬프트·연결·에이전트 설정으로 이동

서재용 설정은 공급자, 프롬프트, 에이전트, 연결 정보를 복제하지 않는다. 값의 단일 기준은 기존 채팅 설정이다.

### 6.7 독서 기록

최근·하이라이트·메모·책갈피 탭을 둔다. 최근은 기존 채팅 활동과 읽기 위치를 조합한다. 하이라이트·메모·책갈피는 실제 데이터가 하나 이상 있을 때만 탭을 보여준다.

## 7. 지표의 의미와 게이지 규칙

열린 결말의 AI 대화에는 실제 완결 지점이 없으므로 다음 값은 만들지 않는다.

- 완독률 또는 이야기 진행률
- 페이지 수와 남은 독서 시간
- 별점
- 자동으로 꾸며낸 장 수
- 활동 추적 없이 계산한 독서 시간

대신 검증 가능한 값만 표시한다.

| 표시 | 데이터 원천 | 의미 |
| --- | --- | --- |
| `문장 184개` | 기존 message-count API | 현재 기록의 실제 메시지 수 |
| `새 문장 3개` | `unreadCounts`와 영속 선톡 metadata | 읽지 않은 실제 메시지 수 |
| `오늘 22:14에 읽음` | 읽기 위치의 `updatedAt` | 마지막 위치 저장 시각 |
| `본문·서신` | 작품에 연결된 chat mode | 실제로 열 수 있는 기록 종류 |
| `2 / 4` | `activeSwipeIndex`와 swipe 개수 | 현재 답변 후보 위치 |
| 얇은 위치 막대 | 현재 렌더링한 대화의 스크롤 | 이야기 완성도가 아닌 현재 문서 위치 |

추후 독서 시간 기능을 넣는다면 뷰어가 전면에 있고 문서가 보이며 최근 입력이 있을 때만 센다. 생성 대기, 백그라운드 통화, 장시간 미동작은 제외한다.

## 8. 기존 기능 연결표

| 화면 동작 | 연결할 기존 구현 |
| --- | --- |
| 열기·이어 읽기 | `setActiveChatId(chatId)` 후 읽기 위치 복원 |
| 최신 미리보기·시각 | 홈 피드와 `lastMessageAt` |
| 새 문장 배지 | `unreadCounts`와 영속 선톡 metadata |
| 보내기 | 기존 `ChatInput`·`ConversationInput` |
| 생성 중단 | 현재 abort controller와 `stopGeneration` |
| 편집 | 기존 메시지 편집 mutation |
| 재생성 | 메시지 ID를 받는 기존 generation hook |
| 스와이프 | 기존 swipe 목록과 `activeSwipeIndex` |
| 번역 | 기존 저장형 번역 흐름 |
| 듣기 | 기존 TTS 메시지 동작과 캐시 |
| 전화 | 기존 active Conversation call snapshot과 call 테이블 |
| 분기 | 기존 branch metadata와 분기 패널 |
| 기억·로어북·에이전트 | 고급 설정에서 기존 채팅 설정 열기 |
| 검색 | 기존 전역·채팅 검색을 독서 용어로 표시 |

서재 셸은 이 동작들을 호출만 하며 같은 비즈니스 로직을 다시 구현하지 않는다.

## 9. 화면 상태와 예외 처리

| 상태 | 화면 처리 |
| --- | --- |
| 빈 서재 | 설명 한 줄과 `첫 작품 만들기` 버튼 한 개 |
| 표지 없음 | 단색 면과 제목 타이포그래피, 이니셜 아바타는 사용하지 않음 |
| 오프라인 | 마지막 캐시 목록과 읽기 전용 본문, 전송 버튼 비활성 이유 표시 |
| 생성 중 | 본문 아래 상태 한 줄과 중단 버튼 |
| 생성 실패 | 해당 메시지 위치에서 재시도, 작품 화면으로 이동시키지 않음 |
| 삭제된 스와이프의 주석 | 주석 보존 후 `위치 다시 연결` 표시 |
| 통화 최소화 | 헤더 아래 한 줄 바를 유지하고 누르면 복원 |
| 키보드 표시 | 입력창과 최신 답변이 안전영역 안에 남음 |
| 표지 로드 실패 | 텍스트 표지로 대체하고 재시도는 백그라운드 처리 |

## 10. 시각 밀도 기준

- 화면마다 주 동작은 하나만 둔다.
- 제목 아래 메타데이터는 한 줄을 넘기지 않는다.
- 홈의 최근 작품은 최대 세 개다.
- 독립적으로 누를 필요가 없는 영역은 카드로 감싸지 않는다.
- 컨테이너보다 여백과 구분선을 우선한다.
- 터치 영역은 최소 44px, 아이콘의 시각 크기는 20~24px로 유지한다.
- 부가 동작은 선택·탭·길게 누르기·더보기 전에는 숨긴다.
- 본문 글꼴은 엔진 기본값과 사용자 읽기 설정을 따른다.
- 지향색은 의미 토큰으로만 사용하며 목업의 베이지색을 고정하지 않는다.
- 다크 모드는 단색 독서 면을 쓰고 본문 뒤에 블러를 적용하지 않는다.

## 11. 성능 기준

- 전체 DOM 대상 `MutationObserver`를 두지 않는다.
- 행마다 타이머를 만들지 않고 기존 공용 시계를 재사용한다.
- 긴 작품·기록 목록은 가상화한다.
- 작품 요약은 한 API에서 묶어 받고 표지마다 별도 요청을 만들지 않는다.
- 표지는 썸네일을 요청하고 화면 밖 이미지는 지연 디코딩한다.
- 읽기 위치 저장은 지연·멱등 쓰기로 처리한다.
- 활성 뷰어의 채팅 컴포넌트만 마운트한다.
- 레이아웃을 계속 바꾸는 애니메이션을 피하고 모바일과 동작 줄이기 설정에서는 장식을 끈다.

## 12. API 설계

```text
GET    /api/library/works
POST   /api/library/works
GET    /api/library/works/:id
PATCH  /api/library/works/:id
DELETE /api/library/works/:id
POST   /api/library/works/:id/chats
DELETE /api/library/works/:id/chats/:chatId
GET    /api/library/reading-state/:chatId
PUT    /api/library/reading-state/:chatId
GET    /api/library/works/:id/annotations
POST   /api/library/works/:id/annotations
PATCH  /api/library/annotations/:id
DELETE /api/library/annotations/:id
```

`GET /api/library/works`는 표지 썸네일 URL, 포함 모드, 최근 채팅 ID·시각, 메시지 수, 읽지 않은 수를 한 응답에 담는다. 목록 화면이 채팅 원문 전체를 받거나 작품별로 추가 요청하지 않도록 한다.

## 13. 호환성과 백업

- 작품 metadata가 없는 가져오기 파일은 가상 작품으로 보인다.
- 기존 채팅 URL과 딥링크는 계속 작동한다.
- 단계적 배포 동안 기존 데스크톱 셸로 돌아갈 수 있다.
- 커스텀 테마는 의미 토큰을 제공하며 글꼴과 독서 색을 하드코딩하지 않는다.
- 백업에는 신규 테이블과 nullable 채팅 연결을 포함한다.
- 작품 연결을 해제해도 채팅은 남는다.
- Conversation·Roleplay 연결이 모드 간 컨텍스트의 기준이다. 같은 작품 소속이라는 이유만으로 프롬프트를 공유하지 않는다.

## 14. 구현 순서

1. 데이터·호환성: 작품 테이블, 채팅 연결, 가상 작품 조회, 폴더 범위, 백업·내보내기
2. 서재 셸: 홈, 서재, 작품 정보, 하단 내비게이션, 검색
3. 뷰어 연결: 기존 Roleplay·Conversation을 감싸되 메시지 동작은 복제하지 않음
4. 읽기 위치: 저장, 복원, 스와이프 위치 동기화
5. 주석: 책갈피를 먼저 구현하고 메모·하이라이트·목차 지점을 순차 추가
6. 외부 사용 보완: 최근 앱 미리보기 가리기 옵션과 빠른 중립 화면
7. 회귀 검증과 단계 배포

기능 플래그 `libraryShellV1` 아래에서 신규 셸을 먼저 활성화한다. 데이터 스키마는 플래그와 무관하게 후방 호환되어야 하며 플래그를 꺼도 기존 채팅 화면에서 모든 기록에 접근할 수 있어야 한다.

## 15. 검증 항목

- 신규·기존 채팅이 데이터 변환 실패 없이 작품으로 열린다.
- 작품을 열면 현재 UI와 동일한 chat ID, 메시지, 스와이프 상태에 도달한다.
- 외부 셸에는 AI, 캐릭터 채팅, 모델, 프롬프트, TTS, Roleplay 용어가 노출되지 않는다.
- 진행률, 페이지, 시간, 별점, 목차 수를 임의로 만들지 않는다.
- 모바일 키보드가 열려도 최신 답변과 입력창을 사용할 수 있다.
- 재생성, 편집, 스와이프, 번역, TTS, 통화, 분기, 기억, 로어북, 에이전트가 기존과 동일하게 작동한다.
- 작품 1,000개에서도 전체 채팅 기록과 원본 크기 표지를 불러오지 않고 목록을 탐색할 수 있다.
- 사용자 글꼴, 지향색, 라이트·다크 모드, 동작 줄이기, 글자 200% 확대가 유지된다.
- 뒤로가기는 뷰어→작품 정보→이전 서재 위치 순서로 한 번씩만 이동한다.
- 생성·편집·삭제·스와이프 후 채팅이 홈으로 이탈하지 않는다.
- 백업 후 복원하면 작품 묶음, 읽기 위치, 책갈피와 주석이 보존된다.

## 16. 완료 정의

구현 완료는 목업과 비슷하게 보이는 상태가 아니라 다음 세 조건을 모두 만족하는 상태다.

1. 서재 화면만 본 사람은 일반 독서 앱으로 인식한다.
2. 작품 안에서는 기존 AI 채팅의 핵심 편의 기능을 더 적은 조작으로 사용할 수 있다.
3. 신규 작품 계층을 제거하거나 기능 플래그를 꺼도 기존 채팅 데이터와 생성 경로가 손상되지 않는다.
