# 다음 업데이트 개발자 노트 (2차)

작성: 2026-10-24 08시 · 기준: `main` `cbae575` (PR #20 병합. #18 리더 1차, #19 통합 기억, #20 설정·목록·UI 관리 포함)

이 문서는 **설계 초안**이다. 구현은 사용자가 "작업 시작"을 명시한 뒤에 한다.
사용자 결정은 하단 "사용자 결정 기록"에 남긴다.
"원인 후보"는 코드를 읽고 세운 가설이며, 측정 전까지는 사실로 취급하지 않는다.

## 0. 원칙

- 우선순위: 기존 기능 보존 > 호환성 > 요청 완전 구현 > 검증 > 최적화.
- 테스트는 **고친 항목당 한 번**만 돌린다. 전체 스위트를 반복해서 돌리지 않는다. 회귀 비교는 실패한 테스트만 `main`에서 다시 돌려 확인한다.
- 기능 단위마다 커밋 + 푸시 + 원격 확인. 실기기 확인 전에는 "미검증"으로 표시한다.

## 1. 채팅방 진입 렉 (특히 RP)

### 1-1. 측정 먼저

- PC·모바일 Chromium에서 "방 클릭 → 첫 메시지 표시"와 "입력 가능"까지의 시간을 잰다.
  - 같은 방(메시지 50·300·1000개)을 RP·Convo로 각각 연다.
  - 비교 대상: `main`과 순정 `baseline/marinara-v2.5.1`.
- 브라우저 Performance 기록으로 긴 작업(long task)과 네트워크 요청 수·크기를 남긴다.
- 서버에서는 방 진입 때 호출되는 API별 응답 시간과 크기를 기록한다.

### 1-2. 원인 후보 (코드 확인, 측정 전)

1. **통합 기억 버블의 5초 주기 조회**: RP 방은 항상 `CommittedMemoryBubble`을 띄운다(`ChatRoleplaySurface.tsx`).
   - 이 버블은 `useCommittedMemory`로 `/committed-memory` 상태를 **5초마다** 조회한다.
   - 서버는 조회할 때마다 채팅 메시지 전체를 읽어 대조하고, 상태 전체(묶음·사실·되돌리기 기록의 `before` 사본 포함)를 돌려준다.
   - RP에서만 렉이 심한 점, 방이 길수록 무거워지는 점과 맞는다. **가장 먼저 확인한다.**
2. **메시지마다 붙는 UI 관리 처리**(#20): 메시지 도구 줄마다 `MessageToolsLayout`이 레이아웃 효과 하나와 `MutationObserver` 하나를 만든다.
   - 메시지가 많으면 첫 표시 때 비용이 쌓인다.
3. **채팅 설정 창의 진입 시 마운트**: `ChatSettingsDrawer`(약 1만 줄)가 숨김 상태로도 방과 함께 마운트되는지 확인한다.
   - 탭(#20)으로 보이지 않는 섹션까지 전부 렌더하는지도 본다.
4. 리더 화면(형광펜·메모·발췌, 문단 번역 정렬)이 진입 때 전체 메시지를 다시 계산하는지 확인한다.

### 1-3. 개선 방향 (측정 결과에 따라 확정)

- 기억 상태:
  - 버블에는 **개수만 담은 가벼운 응답**을 쓰고, 주기 조회는 창이 열려 있을 때만 한다.
  - 그 밖에는 답장 생성·정리 직후에 무효화한다.
  - 되돌리기 기록의 `before` 사본은 상태 응답에서 빼고 필요할 때 따로 받는다.
- 메시지 도구 레이아웃:
  - 줄마다 관찰하지 말고 CSS 변수/속성 한 번으로 적용한다(순서·숨김은 CSS로 가능).
  - '더보기'만 상태가 필요하다.
- 보이지 않는 채팅 설정 탭·섹션은 처음 열 때 렌더(lazy)한다.
  - 단, 기존 테스트와 단축 이동(옴니바)이 섹션 DOM을 기대하므로 이동 경로를 함께 바꾼다.
- 완료 기준: 측정한 진입 시간이 개선 전보다 줄었다는 수치를 노트에 남긴다. 기존 E2E에 회귀가 없어야 한다.

## 2. 화면 색을 설정창에서도

- 현재 화면 색 4종(화이트·크림·먹색·블랙)은 읽기 설정에만 있다. 앱 테마도 함께 바뀌는 구조다(#18).
- 순정 설정창의 Appearance(화면) 그룹에 같은 선택지를 둔다.
  - 같은 저장값(`readerPreferences.shared.page`)을 쓴다.
  - 어느 쪽에서 바꿔도 다른 쪽에 바로 반영된다.
- 기존 테마 선택(라이트·다크 등)과의 관계: 화면 색을 고르면 테마가 따라 바뀌는 지금 규칙을 유지한다.
  - **결정 (2026-10-24 08:08)**: 설정창에는 **화면 색 4종만** 둔다. 기존 테마 선택 UI는 설정창에서 보이지 않게 하고, 저장값과 사용자 지정 테마 데이터는 그대로 둔다.
- 검증: 설정창에서 변경 → 새로고침 → 유지, 리더 설정과 양방향 일치(E2E 1개).

## 3. 몰입 모드에서 숨겨지지 않는 것 (버그)

- 원인(코드 확인): 몰입 모드 숨김 목록(`globals.css`의 `html[data-reader-focus="true"] :is(...)`)에 다음이 없다.
  - **'상단'에 둔 창의 버블** `.mari-window-bubble`
  - **기억 정리 버블** `[data-memory-commit]`
  - (아마도) 열린 상태로 남은 분리 창
- 수정:
  - 몰입 중에는 위 요소를 숨긴다.
  - 몰입을 끄면 원래 위치·상태로 돌아온다. 위치 저장값은 건드리지 않는다.
  - 상단바를 다시 부르는 위쪽 가장자리 동작(PC hover, 모바일 탭)은 그대로 둔다.
- 검증: '상단'에 섹션 하나를 두고 통합 기억을 켠 RP 방에서 몰입 → 둘 다 안 보임 → 해제 → 원래 위치(PC·모바일 E2E 1개).

## 4. 목록형 창 전체를 칼로리표·영수증 무드로

### 4-1. 사용자 피드백 (2026-10-24 실기기 캡처)

**캐릭터 목록**

- 상단 '마리나라 서재' 머리와 패널 사이에 미세한 틈이 있다.
- 폴더 머리('1차 / 정사')의 디테일이 부족하다.
- 폴더 안 목록의 왼쪽 세로선·들여쓰기와 굵은 막대가 레퍼런스를 따르지 않는다. 성의 없는 굵은 선으로 보인다.
- 줄마다 중복 정보가 있다(언어 'EN'이 메타와 태그 칩에 두 번, 토큰 줄 등). 줄을 줄인다.
- 태그 칩은 목록에서 뺀다.
- 토큰 수는 영수증의 **가격처럼** 오른쪽 굵은 값으로 보여 준다.
- 동작 아이콘(복제·삭제·채팅 등)은 둥근 칩 대신 디자인에 맞춘다.

**페르소나 목록**

- 캐릭터와 같은 개선을 적용한다.
- 버전·설명 줄 대신 **캐릭터처럼 타이틀/코멘트**를 보여 준다.

**작품 정보**

- 표지 높이가 오른쪽 정보 블록(제목·설명·'이어 읽기')과 맞지 않는다. 맞춘다.
- '이어 읽기' 버튼을 더 슬림하게 한다.

**레퍼런스**: Nutrition Facts 라벨, Hot Sauce Timetable, Class Schedule 영수증, 빈 라벨 틀.

### 4-2. 디자인 원칙 (레퍼런스에서 추출)

- 창 전체가 **하나의 라벨**이다. 테두리 안에 큰 굵은 제목을 둔다(예: "캐릭터").
  - 제목 바로 아래 한 줄 요약(예: "8명 · 폴더 2")을 둔다.
- 굵은 막대는 **3단계**만 쓴다.
  - 제목 아래 가장 굵은 막대
  - 구획 사이 중간 막대
  - 행 사이 1px 가는 선
  - 이 밖에 임의의 두께는 쓰지 않는다.
- 행 구성:
  - 왼쪽: 굵은 이름 + 한 줄 보조(타이틀/코멘트)
  - 오른쪽: 굵은 값(토큰 수 등)
  - 들여쓰기는 하위 항목에만 쓴다(레퍼런스의 "Saturated Fat"처럼).
- 구획 머리(폴더·즐겨찾기 등): 굵은 글씨 + 오른쪽 개수, 위에 중간 막대.
- 아이콘: 가는 선 아이콘만, 테두리·배경 칩 없이 쓴다. 행 오른쪽 값과 겹치지 않게 hover/탭 시에만 보인다(모바일은 ⋯ 하나로 모은다).
- 색:
  - 현재 테마의 전경색을 잉크색으로 쓰고 회색 단계는 최소로 한다.
  - 강조색은 선택 상태에만 쓴다.
  - 라이트·다크 모두 같은 구조다.
- 글꼴: 앱 글꼴을 유지한다. 제목·값만 굵게, 숫자는 `tabular-nums`.

### 4-3. 적용 범위

- 창 전체:
  - 연결, 로어북, 캐릭터, 페르소나, 프리셋, 에이전트, 설정창
  - 헤더, 상단 버튼 묶음, 검색·정렬, 필터 칩, 빈 상태 포함
- 설정창은 #20의 그룹 토글을 **라벨 구획**으로 바꾼다. 접은 상태가 라벨의 한 줄처럼 보이게 한다.
- 작품 정보 화면은 4-1의 크기·버튼 조정만 한다.
- 데이터·동작(드래그 정렬, 폴더, 선택 모드, 가져오기 등)은 바꾸지 않는다. 마크업은 필요한 만큼만 바꾸고, 공통 컴포넌트(`ReceiptPanel`, `ReceiptRow` 등)로 묶어 7개 창에서 재사용한다.

### 4-4. 결정 (2026-10-24 08:08)

1. **페르소나·캐릭터 창 상단의 '다운로드 / 라이브러리 열기' 줄과 '검색 · 정렬' 줄을 목록 창에서 뺀다.**

   - 새로 만들기(+)는 머리에 남긴다.
   - 같은 구성을 다른 목록 창에도 적용할지는 구현 때 화면을 보고 맞춘다.
2. **토큰 수는 가격처럼** 보인다.

   - 단위 '토큰'은 목록 머리의 열 이름에 한 번만 둔다(레퍼런스의 "% Daily Value", "Release Date"처럼).

   - 태그 필터(목록 위 필터 칩)는 그대로 둔다. 목록에서 태그로 거르는 기능이기 때문이다.
