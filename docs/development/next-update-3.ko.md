이 문서는 **설계 초안**이다. 구현은 사용자가 "작업 시작"을 명시한 뒤에 한다.
사용자 결정은 하단 "결정 필요"와 "사용자 결정 기록"에 남긴다.
"원인 후보"는 코드를 읽고 세운 가설이며, 확인 전까지는 사실로 취급하지 않는다.

## 0. 원칙

- 우선순위: 기존 기능 보존 > 호환성 > 요청 완전 구현 > 검증 > 최적화.
- 테스트는 고친 항목당 한 번만 돌린다. 실기기에서만 확인할 수 있는 항목은 사용자가 확인한다(PR 체크리스트로 넘긴다).
- 기능 단위마다 커밋 + 푸시 + 원격 확인.
- 삭제 요청은 "화면에서 숨김"과 "기능 삭제"를 구분한다. 기능 삭제는 저장된 데이터 처리 방법까지 정한 뒤에 한다.

## C1. 파비콘 · 모바일 웹앱 아이콘 · 이름 커스텀

현재: `packages/client/public/manifest.json`(정적), `favicon.png`, `icon-192.png`, `icon-512.png`, `index.html`의 `<link rel="icon|manifest|apple-touch-icon">`.

방법:

- 설정에 "앱 아이콘과 이름" 구획을 추가한다: 이름(긴 이름·짧은 이름), 아이콘 이미지 1장 업로드, 초기화.
- 업로드한 이미지는 서버가 192·512·파비콘 크기로 만들어 저장하고, `manifest.json`과 아이콘 주소를 설정값에서 동적으로 내보낸다. 설정이 없으면 지금 파일을 그대로 쓴다.
- 탭 제목과 `apple-mobile-web-app-title`도 같은 이름을 쓴다.

한계:

- 이미 홈 화면에 추가한 앱은 OS가 아이콘을 다시 읽을 때까지 예전 아이콘으로 남을 수 있다. iOS는 다시 추가해야 바뀌는 경우가 많다. 설정 안내문에 적는다.
- 서버 쪽 작업이 필요하다(업로드 · 크기 변환 · 동적 manifest). 이미지 변환에 쓸 수 있는 의존성이 서버에 이미 있는지 먼저 확인한다.

## C2. 모바일 뒤로가기 흐름

요청: 뒤로가기를 누르면 화면을 한 단계씩 닫다가 홈(서재)까지 나오고, 홈에서는 **두 번 연속** 눌러야 앱이 닫힌다.

방법:

- 지금 있는 `useBackDismiss`(모달·작품 정보 등 닫기)와 `modal-overlay-registry`의 순서를 그대로 쓰고, 마지막 단계만 추가한다.
- 홈에 도착하면 history에 보초 항목을 하나 쌓는다. 첫 뒤로가기는 "한 번 더 누르면 종료됩니다" 알림을 띄우고 보초를 다시 쌓는다. 2초 안에 다시 누르면 보초 없이 빠져나간다.
- 채팅·리더 화면에서 뒤로가기를 누르면 작품 정보 → 홈 순서로 나온다. 지금 경로를 먼저 지도로 그려 빠진 단계가 없는지 확인한다.

한계:

- 브라우저 탭에서는 "앱 종료"가 아니라 이전 페이지(또는 빈 탭)로 나가는 것이다. 홈 화면에 추가한 웹앱(standalone)에서는 앱이 닫힌다.
- Android APK(`android/MainActivity.onBackPressed`)는 WebView 기록으로 움직이므로 웹 쪽 처리로 같이 맞춰진다. APK 빌드는 이번 범위에 넣을지 결정 필요 ⑤.
- iOS는 뒤로가기 버튼이 없어 해당되지 않는다(스와이프 뒤로가기는 브라우저 기록을 따른다).

## D1. 확장 병합: 말랑 리모콘 1.2.0

원본: `Personal Extensions/personal-extension` (manifest · `extension.js` 2,987줄 · `extension.css`). `full_page_access`, `marinara.storage` 사용.

원본 기능:

- 떠 있는 리모콘(왼쪽/오른쪽 고정, 자유 이동, 사이드바 고정, 간단/목록 모드).
- 화면의 아무 버튼이나 "골라서" 리모콘에 등록한다. 등록한 버튼은 원래 버튼을 대신 눌러 준다.
- 등록 버튼을 분류 줄(라인)로 묶고, 접고, 끌어서 정렬한다. 이름·아이콘(Lucide)을 바꾼다. 잠금, 닫기 버튼 연결, 연결이 끊긴 버튼 정리 기능이 있다.
- 원래 버튼의 숫자·상태 배지를 리모콘에 따라 표시한다(끔 / 조작할 때 / 응답 받을 때 / 상시, 확인 간격).
- 메시지 이동: 이전·다음 메시지, 번호로 이동(입력창에 `/goto N`을 넣어 보낸다).
- 코드 블록에 복사 버튼을 붙인다(`.mari-md-codeblock`).
- 원본은 아이콘을 `raw.githubusercontent.com`에서 받아 온다(네트워크 필요).

병합 방향(초안):

- 엔진 기본 기능으로 넣는다(확장 관리 없이 동작). UI 관리(#20)의 "상단" 배치와 역할이 겹치므로, 리모콘은 UI 관리의 배치 하나로 두는 안을 기본으로 한다(결정 필요 ⑥).
- 버튼 등록: "화면의 아무 버튼이나 고르기"는 엔진이 바뀔 때 쉽게 끊긴다. 엔진이 아는 동작 목록(채팅 설정 구획, 메시지 도구, 상단 버튼, 패널 열기)에서 고르는 방식을 기본으로 하고, 아무 버튼 고르기를 남길지는 결정 필요 ⑦.
- 메시지 이동은 `/goto`를 입력창에 써서 보내지 않고, 엔진의 이동 함수를 직접 부른다(입력 중인 초안이 사라질 위험이 없다).
- 아이콘은 엔진에 이미 들어 있는 `lucide-react`에서 고른다. 외부에서 받아 오지 않는다.
- 저장: `marinara.storage` 대신 UI 저장소(ui.store, 설정 동기화 포함)에 넣고, 원본 저장값(`marinara.manual-sidebar.v1`)이 있으면 한 번 옮겨 온다.

## D2. 확장 병합: 웹폰트 매니저 1.0.1

원본: `extension.js` 949줄. `/api/fonts`(엔진 글꼴 폴더)를 읽는다.

원본 기능:

- `@font-face` 또는 `@import` 코드(HTTPS 주소만)를 붙여 넣어 웹폰트를 등록하고 삭제한다.
- 적용 대상 3곳(UI · RP · CONVO)마다 글꼴, 크기(10~48px), 자간(-2~6px), 행간(1~3)을 정한다.
- 엔진 글꼴 폴더의 글꼴도 같은 목록에 보여 준다.

병합 방향(초안):

- 엔진에는 이미 앱 글꼴 설정(`fontFamily`)과 리더 설정(글꼴·크기·자간·행간)이 있다. 새 창을 만들지 않고, 등록한 웹폰트가 **기존 글꼴 선택 목록에 함께 나오게** 하는 안을 기본으로 한다(결정 필요 ⑧).
- 웹폰트 등록 화면은 설정 › 모양에 "웹폰트" 구획으로 넣는다. 등록한 CSS는 서버 설정에 저장해 기기 사이에 동기화한다.
- 안전: HTTPS `@font-face` / 조건 없는 `@import`만 받는다는 원본 규칙을 그대로 쓴다. CSS 안에 다른 규칙이 섞이면 거절한다.
